# Проверка параллельного расчёта сценариев

На одном и том же графе `best`, α = 0,05, сравнили один и два локальных рабочих процесса. Граф содержит 180 вершин и 5 642 ребра. Для нагрузки взяли 24 наиболее населённых города и по очереди имитировали удаление каждого. Каждое удаление выполняется независимо на исходном графе. Город с равным населением упорядочивается по UUID.

| Рабочие процессы | Прогон 1, с | Прогон 2, с | Прогон 3, с | Медиана, с |
|---|---:|---:|---:|---:|
| 1 | 4,148 | 4,038 | 4,845 | 4,148 |
| 2 | 2,316 | 2,380 | 2,872 | 2,380 |

На проверенном объёме отношение медиан равно 1,74. Во всех запусках для каждого города совпали число достижимых пар до и после удаления, число сопоставимых пар и суммы времён. Результаты также сравнили с прямым вызовом той же функции без пула.

Замер выполнен 26 ноября 2026 года, МСК, на Windows 11 Pro, Intel Core i5-12400F, 31,84 ГиБ, Python 3.12.3. На каждый прогон поднимается новый пул. Время включает запуск процессов, передачу графа и готовых исходных расстояний, вычисления и сбор результатов. Скачивание, нормализация и построение графа измеряются отдельно в [сквозном прогоне](https://github.com/AlexKeyyyy/transport-connectivity/blob/b4024c9596d0258af40c8e13affb304b83a0c9f3/benchmarks/README.md).

```powershell
python scripts/data/benchmark_removals.py
```

Запуск использует нормализованный основной снимок. При другом расположении передайте `--snapshot`. Скрипт проверяет контрольные суммы, выбирает те же случаи и выводит времена в JSON. [Исходный код проверки](../../scripts/data/benchmark_removals.py).

Это параллельный расчёт на одной машине. В многосерверной схеме каждому исполнителю можно передать неизменяемый граф один раз, затем отправлять списки удаляемых городов. Следующий измеримый шаг — повторить тот же набор на двух узлах и добавить к времени вычисления передачу графа, ожидание самого медленного блока и сбор результатов.
