# Промежуточный отчёт и план команды

Состояние на 3 ноября 2026 года. Проект: анализ транспортной связности городов
России. Фиксированного срока сдачи нет. Это отчёт о текущем состоянии и план
достижения ближайших результатов; незавершённые работы не объявляются готовыми.

### Лине

Начать с реальных полей пилота. Сначала передать Елисею минимальный контракт:
устойчивые ID городов с пространством имён, направление, транспорт, единицы,
источник/версия, правила пропусков и дубликатов. Для городов полного набора
нельзя предполагать наличие OSM ID. После согласования завершить модель,
исходники и SVG диаграмм, описание потоков данных и нужные ADR.
Передать схемы Мадине для пакета. Ориентир трудоёмкости — 2–3 рабочих дня.

### Мадине

Сразу начать ограничения и статистики пилота. Для внешних численных лимитов
указать первичную документацию и дату проверки. Описать рост числа направленных
пар N × (N − 1), различать измерения и оценки масштабирования. На основе модели
Лины подготовить схему индекса ES и примеры запросов; если PoC не запускался,
так и написать. После #7/#8 получить manifest и run-report, сверить цифры,
собрать README с относительными ссылками на материалы. Ориентир — 2–3 рабочих
дня плюс сборка результатов команды.

### Елисею

Сначала отделить скачивание полного CSV от формирования пилота и live API.
Добавить CLI, проверку кэша/архива, ограниченные повторы, manifest и offline-тесты.
Затем реализовать обработчик по контракту Лины: км → м, ч → с, сохранение
направлений и причин пропусков, проверки ID/координат/чисел/дубликатов.
Не заменять отсутствие маршрута нулём. Прогнать все строки и повторить запуск
на том же входе. Ориентир: #7 — 1–2 рабочих дня, #8 — 2–3 после контракта.

## Порядок выполнения и приёмка

1. Параллельно: Лина согласует контракт; Елисей делает #7; Мадина исследует
   ограничения и пилотные объёмы.
2. После контракта и полной выгрузки Елисей завершает #8; Лина передаёт схемы
   Мадине. Для закрытия исходного M0-3 достаточно его собственных критериев;
   результаты M1 используются для расширенного промежуточного отчёта.
3. Мадина собирает пакет, Алексей проверяет PR и доказательства. Каждый
   работает в отдельной ветке от актуального main и прикладывает команды
   воспроизведения. Сроки выше — оценки трудоёмкости, а не дедлайны.
4. В отчёт добавляются ссылки на merged PR, manifest и run-report. Заявить
   готовность трёх основных результатов можно после выполнения критериев #7/#8.

Для полного прогона должны сходиться числа:

```text
вход = сохранённые + отклонённые + отдельно учтённые удалённые дубликаты
```

Run-report должен содержать SHA-256 входа, commit кода, параметры, время UTC,
число записей/городов, причины отклонений и пропусков, распределение по транспорту,
время работы и измеренную пиковую память с методом измерения. Повторный запуск
должен давать те же нормализованные данные. Большие входы и результаты остаются
в игнорируемых `data/raw/` и `data/processed/`; в Git — небольшие доказательства.

Проверка текущей базы при подготовке отчёта: Python 3.12, `pytest` — 2 passed,
`ruff check` — All checks passed. Это smoke-тесты существующего пакета;
для приёмки коннектора и обработчика нужны новые тесты по #7/#8.

## Следующие этапы

PostgreSQL/PostGIS остаётся основным хранилищем; Neo4j и Elasticsearch —
восстанавливаемыми производными представлениями. Измерение маршрута не является
автоматическим GraphEdge. После этой сдачи отдельными Issues планируются
загрузка нормализованных данных в БД, методика GraphEdge/GraphSnapshot,
графовая проекция и расчёты доступности, ключевых узлов и устойчивости сети.
