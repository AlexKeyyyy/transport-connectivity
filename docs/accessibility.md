# Доступность городов по времени в пути

Расчёт по задаче [#33](https://github.com/AlexKeyyyy/transport-connectivity/issues/33).
Использован снимок «Если быть точным» от 29 июня 2026 года
`tochno_intercity_v20260629`. Он содержит 180 городов и 96 660 измерений.
Результаты ниже получены 24 ноября 2026 года по московскому времени из
отдельной базы PostgreSQL 17.5 с PostGIS 3.5.2.
[Контрольные суммы и баланс снимка](../deliverables/interim/evidence/verification.md)

## Метод расчёта

Команда берёт направленные времена из нормализованной матрицы. Слои
`road` и `rail` используют время источника. Для `best` берётся минимум
доступных времён по автомобилю, поезду и самолёту. К полётному времени
добавлены 10 800 с. Используется та же функция `layer_times`, что и в
[методике графа](graph-methodology.md), до прореживания.

Для каждого отправления считаются два показателя:

- `reach_cities` — число других городов с временем не больше порога.
- `reach_population` — сумма известного населения этих городов.
  Город без значения населения учитывается в числе направлений. В текущем
  снимке население известно для всех 180 городов.

Пороги — 3, 6 и 24 часа (10 800, 21 600 и 86 400 с). Например, поездка
ровно 6 часов попадает в шестичасовой результат. При равном охвате города
упорядочиваются по UUID. Нижнее десятипроцентное множество содержит 18
городов из 180. Для сводки по регионам каждое отправление имеет одинаковый
вес. Региональные названия и охват городов взяты из снимка.

## Повторить расчёт

В окружении с установленным пакетом настройте подключение к PostgreSQL.
Загрузите снимок по [инструкции](../data/README.md), затем выполните:

```bash
python -m transport_connectivity.cli accessibility
python -m transport_connectivity.cli accessibility
```

Чистая база с загруженным снимком даёт `runs_created: 12` и
`runs_reused: 0`, повтор — `runs_created: 0` и `runs_reused: 12`.
Команда печатает JSON с полем `best_half_day`: из него получены оба
рейтинга, нижние 10% городов и региональная таблица. Аргумент
`--snapshot-id` выбирает другой загруженный снимок.

| Алгоритм | Слой | Запусков | Строк на запуск | Из них время определено |
|---|---|---:|---:|---:|
| `threshold_accessibility` | road, rail, best | 9 | 360 | — |
| `travel_times` | road | 1 | 32 220 | 29 756 |
| `travel_times` | rail | 1 | 32 220 | 28 056 |
| `travel_times` | best | 1 | 32 220 | 30 554 |

Девять пороговых запусков записывают всего 3 240 значений, три запуска
времени — 96 660. Для времени в пути сохраняются все направленные пары
разных городов, включая `NULL` при отсутствии исходной оценки. Каждый
запуск связан со снимком, имеет статус `ready` и `scenario IS NULL`.
Параметры пороговых запусков содержат `layer`, `threshold_sec` и
`air_access_sec`. Для времени в пути достаточно `layer`. При подключении #36 фильтр
по слою и порогу должен учитывать дополнительный `air_access_sec`.
Команда публикует `road`, `rail` и `best`. В `best` учтено полётное время.
[Справочник показателей](data-model.md#показатели-metric_result)

## Результаты для слоя best за шесть часов

города с 1 023 778 жителями. Все десять лидеров по доступному населению
находятся в Московской области. Одинцово и Щёлково дают по 102 направления,
