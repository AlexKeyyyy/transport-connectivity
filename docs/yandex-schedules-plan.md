# План: прямые рейсы из Яндекс Расписаний

Статус: **сбор идёт** (Issue [#31](https://github.com/AlexKeyyyy/transport-connectivity/issues/31)),
дата снимка D = **1 декабря 2026** (вторник). Документ отвечает, какие данные о рейсах нужны
графу, как получить их при суточной квоте ключа и сколько это займёт. Запуск сбора —
[data/README.md](../data/README.md#прямые-рейсы-яндекс-расписаний), ограничения API —
[constraints.md](constraints.md#яндекс-расписания).

## Зачем

«Если быть точным» даёт время поездки между любыми двумя городами, в том числе с
пересадками, и считает его по средней скорости. Для анализа устойчивости нужны
**непосредственные связи** ([ADR 0003](adr/0003-measurement-vs-graph-edge.md)): есть ли
прямой поезд или самолёт из города A в город B и сколько таких рейсов. Тогда можно задать
вопрос «что будет со связностью, если отменить рейсы через узел X».

Результат сбора — для каждой упорядоченной пары наших городов и вида транспорта
(`train`, `plane`): число прямых рейсов на дату D и минимальное время в пути.
Как превратить это в ребро графа, решает методика графа
([#28](https://github.com/AlexKeyyyy/transport-connectivity/issues/28)), а не этот сбор.

## Почему не перебором пар

Метод `search` отвечает на вопрос об одной паре. Для 180 городов это 32 220 запросов на
вид транспорта, то есть 65 дней квоты в 500 запросов. Сбор строим наоборот: от станций.
Запрос `schedule` по станции возвращает все её рейсы, а `thread` по рейсу — все его
остановки. Один поезд Москва — Владивосток даёт сразу все пары наших городов на маршруте.

Другие источники проверены и не подходят: у РЖД и Туту.ру нет открытого API, OpenStreetMap
и справочник маршрутов Travelpayouts не дают времени и частоты, авиаданные FlightRadar24 и
OAG платные. API Яндекс Карт (матрица расстояний, изохроны) считают поездки на машине —
это уже есть в «Если быть точным».

## Шаги

| Шаг | Метод | Что получаем |
|---|---|---|
| 1 | `stations_list` | Все станции России с кодами и координатами (34 МБ, 1 запрос) |
| 2 | — (локально) | Наш город → населённый пункт Яндекса |
| 3 | `schedule`, самолёты | Вылеты каждого аэропорта на D; прилёты на D и D+1 |
| 4 | `schedule`, поезда | Отправления на D с основных ЖД-станций городов |
| 5 | `thread` | Остановки каждого поезда, отправляющегося на D |
| 6 | `schedule` + `thread` | Станции наших городов из остановок, ещё не опрошенные; повтор, пока появляются новые |
| 7 | — (локально, следующий PR) | Пары наших городов на каждом рейсе → прямые связи |

**Шаг 2 — сопоставление городов.** У населённых пунктов Яндекса нет координат, есть только
у станций. Кандидаты — населённые пункты России с тем же названием (без учёта регистра,
ё = е); из них берётся тот, чья ближайшая станция ближе всего к точке города, но не дальше
50 км. Название сужает выбор (одноимённых пунктов много — два «Пушкино» в Подмосковье),
расстояние подтверждает. Названия регионов у Яндекса другие («Москва и Московская
область»), поэтому регион не сравнивается. 50 км, а не 15: у Магадана (39 км) и Магаса
(23 км) единственная станция — аэропорт за городом. Результат —
`city_matching.csv`, в базе — внешний ID в пространстве имён `yandex_settlement`
(таблица `city_external_id`, [модель данных](data-model.md)).

Итог на снимке станций 16.11.2026: **179 из 180** городов. Северск — без совпадения:
у закрытого города нет своего пункта в справочнике.

**Шаги 3–6 — станции.** Только `train` и `plane`: электрички (`suburban`) и автобусы дают на
порядок больше отправлений и откладываются. Это заметное ограничение для городов
Подмосковья (Мытищи, Химки, Подольск и другие): их связь с Москвой держится в основном на
электричках.

- **Самолёты.** Все 104 аэропорта сопоставленных городов. Номер рейса (`uid`) содержит
  дату вылета, поэтому вылет из A и прилёт в B соединяются по `uid` без запроса остановок.
  Прилёты нужны и на D+1: ночной рейс на восток прилетает на следующий день по местному
  времени. Часть аэропортов есть в справочнике, но закрыта (Воронеж): `schedule` отвечает
  404 «станция не найдена», и прилёты для них не запрашиваются.
- **Поезда.** Типы станций у Яндекса размечены неровно: «Новосибирск-Главный» — обычная
  станция, а не вокзал. Опрашивать все ~750 ЖД-станций городов (с товарными и МЦК) дорого,
  поэтому сначала берутся **основные**: вокзалы и станции, название которых начинается с
  названия города (~340). Остальные станции наших городов опрашиваются, если на них
  останавливается уже найденный поезд. Так находятся станции без названия города в имени
  (в Екатеринбурге — ВИЗ, Шарташ) и не тратится квота на станции без поездов дальнего следования.
- **Остановки поезда** (`thread`) запрашиваются **без даты**: дата в этом методе — день
  отправления с начальной станции, и для поезда, найденного в середине маршрута, она
  неизвестна (неверная дата даёт 404 «не ходит»). Без даты API отдаёт ближайший рейс нитки;
  время между остановками у рейсов одной нитки одинаковое. Каждый `uid` запрашивается один раз.

**Шаг 7 — связи.** Для рейса с остановками в наших городах `A, B, C` (в порядке
следования) прямые связи — `A→B`, `A→C`, `B→C`, время — прибытие в B минус отправление из A.
По всем рейсам считаем число рейсов и минимальное время для каждой пары. Ключ рейса — `uid`
нитки + дата отправления + станции посадки и высадки; это закрывает вопрос уникальности из
[#15](https://github.com/AlexKeyyyy/transport-connectivity/issues/15).

## Сколько это займёт

Проба 15–16.11.2026 (15 запросов): ответ `schedule` на дату захватывает утро следующего
дня, поэтому отправления фильтруются по местной дате D; отправлений за день — Шереметьево
303 (4 страницы), Тверь 97, Казанский вокзал 48. У самолётов около 70 % рейсов — в наши
города.

Оценка: самолёты ~500 запросов, поезда — ~400 `schedule` и ~2 000 `thread`. Итого около
3 000 запросов, **6–7 дней** при 500 запросах в сутки. Первыми собираются самолёты — это
меньшая и самостоятельная часть, авиаслой готов примерно через сутки. Фактические числа
записываются в manifest и сюда после сбора.

## Как собираем

- Каждый ответ сохраняется как есть в `data/raw/yandex_rasp_<D>/` вместе с параметрами
  запроса. Что запрашивать дальше, определяется по сохранённым ответам, поэтому сбор
  продолжается с места остановки и не тратит квоту на уже полученные ответы.
- Счётчик запросов по московским суткам не даёт превысить квоту; повторные попытки тоже
  считаются.
- Manifest снимка: дата D, `complete`, причина остановки, сопоставление городов, число
  запросов по методам и статусам, SHA-256 всех ответов.
- Отсутствие рейса, отсутствие запроса и ошибка API различаются: 404 — ответ источника и
  хранится, другие ошибки останавливают сбор; незавершённый сбор (`complete: false`) не
  нормализуется.
- В материалах и на графиках — указание «Яндекс Расписания» как источника (условие API).

## Ограничения результата

- Один день D — это снимок, а не типичная неделя: часть поездов ходит через день.
- Остановки поезда берутся с ближайшего рейса нитки, а не обязательно с рейса на D.
- Рейс на запад, вылетевший с Дальнего Востока сразу после полуночи D, может приземлиться
  на D−1 по местному времени и не попасть в прилёты D и D+1. Нормализация считает вылеты
  без найденного прилёта; если таких рейсов в наши города заметно, прилёты D−1 дозапрашиваются.
- Связь «есть прямой рейс» не говорит о вместимости и цене.
- Города без вокзала и аэропорта получают связи только через «Если быть точным».
- Без электричек и автобусов связность Подмосковья занижена.
