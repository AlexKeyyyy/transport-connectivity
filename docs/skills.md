# Общий набор skills

Skills установлены в `.agents/skills/` и версионируются с проектом. Глобальная
установка, ключи и серверы для чтения инструкций не нужны. Python-библиотеки
и сервисы устанавливаются отдельно, только в задачах их реализации.

## Как начать участнику

1. Получить ветку с этими изменениями; после merge — обновить main обычным pull.
2. Открыть корень репозитория в Codex. Repo skills обнаруживаются автоматически;
   они доступны со следующего хода. Если не появились — перезапустить Codex.
3. Проверить набор: `python scripts/dev/check_harness.py` (Python 3.12+).
4. Дать задачу с номером Issue. Нужный skill можно назвать явно: например,
   «Используй $transport-data-pipeline для Issue #8».

Приватные пользовательские настройки Codex и подключения другим людям не передаются.
Для других агентов, поддерживающих SKILL.md, можно указать каталог явно; их
автоматическое обнаружение и tool mapping нужно проверить отдельно.

|---|---|---|

| `supabase-postgres-best-practices` | SQL, схема, ограничения, индексы и запросы PostgreSQL | Лине, затем разработчику БД |
| `transport-postgis` | Геометрии, CRS, расстояния и spatial joins | Лине и разработчику загрузки |
| `transport-graph-methodology` | Смысл ребра, веса, доступность и допустимые сценарии | Лине и разработчику аналитики |
| `transport-neo4j` | Модель проекции, Cypher, GDS и контроль версии графа | Разработчику графа |
| `transport-elasticsearch` | Mapping cities, поиск и восстановление индекса | Мадине на проектировании, затем разработчику поиска |
| `jupyter-notebook` | Воспроизводимый notebook для исследования или демонстрации | Мадине и разработчику аналитики |

Читается только относящийся к задаче skill и нужные references. Не загружать весь
набор в контекст. Python, тесты и Git не требуют отдельных общих skill-пакетов:
правила проекта уже в AGENTS.md, проверки — в одной команде.

## Обновление

Обновление выполняется отдельным PR: выбрать commit, скачать выбранный каталог
через skill-installer во временное место, прочитать diff инструкций/scripts/references
и лицензию, перенести одобренные изменения и повторить локальные адаптации.
После review пересчитать `files` в lock для изменённого skill; для upstream также
обновить commit и `upstream_files`. Проверка сама ничего не перезаписывает и не
скачивает. Смена lock без review не доказывает надёжность содержимого.

Запустить `python scripts/dev/check.py`, официальный quick_validate из skill-creator
при его наличии и сценарии [harness-evals](harness-evals.md). Для обновлённого helper
проверить реальное исполнение. Доступность GDS/ES/PostGIS проверяется интеграционно
на этапе соответствующего Issue; установка инструкций её не подтверждает.

Как устроен рабочий цикл агента: [harness.md](harness.md).
