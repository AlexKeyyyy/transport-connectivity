# Методика построения графа

Версия методики: `1.0`. Задача: [#28](https://github.com/AlexKeyyyy/transport-connectivity/issues/28). Код: `src/transport_connectivity/graph.py`.

## Зачем нужна методика

Набор «Если быть точным» — это матрица «каждый с каждым»: для каждой из 180 × 179 направленных пар городов и каждого из трёх видов транспорта есть оценка времени в пути ([контракт данных](data-contract.md)). Если считать каждую запись ребром, граф окажется почти полным: из каждого города можно «напрямую» попасть в 179 других. На таком графе кратчайший путь всегда равен прямой записи, а ключевых узлов нет, потому что все города одинаково важны. Удаление ребра тоже ничего не моделирует: закрытая дорога Москва — Орёл не закрывает пару Москва → Орёл, а только убирает одну запись.

Реальная сеть устроена иначе. Из Москвы в Орёл едут через Тулу, и отдельной «прямой связи» нет. Поэтому из матрицы нужно оставить разреженный граф: ребро сохраняется только тогда, когда оно не сводится к пути через другой город. Решение об отделении измерения от ребра зафиксировано в [ADR 0003](adr/0003-measurement-vs-graph-edge.md). Эта методика — то самое утверждённое правило, по которому измерение становится ребром.

| Участок | Время, с |
|---|---:|
| Москва → Орёл (напрямую) | `<t(A,B)>` |
| Москва → Тула | `<t(A,C)>` |
| Тула → Орёл | `<t(C,B)>` |
| Москва → Тула → Орёл (сумма) | `<t(A,C)+t(C,B)>` |
| Отношение обхода к прямому времени | `<ratio>` |

При α = 0,05 / 0,10 / 0,20 ребро Москва → Орёл `<остаётся / удаляется>`.

## Принятые решения

**1. Вершины.** Все 180 городов. Город без рёбер остаётся вершиной: изолированность — тоже результат.

**2. Время по видам транспорта.** Берётся `route_measurement.duration_sec`.

- `road`, `rail` — как в источнике.
- `air` — время источника плюс `AIR_ACCESS_SEC = 10 800` с (3 часа): дорога в аэропорт и из него, регистрация, ожидание.
- Нет измерения (`NULL`) — нет связи этим видом. Источник не утверждает, что маршрута точно нет, поэтому в графе такая пара просто не получает ребра этого вида.

**3. Слои.** Три слоя: `road`, `rail` и `best`. Для пары (A, B) слой `best` берёт минимум из доступных времён трёх видов после поправки для `air`. У ребра запоминается вид, давший минимум; при равенстве выигрывает `road`, затем `rail`. Пересадки между видами в этой версии не учитываются: ребро `best` — это одна поездка одним видом.

**4. Направление.** Граф направленный: A → B и B → A — разные рёбра с разным временем.

**5. Прореживание.** Ребро A → B удаляется, если есть город C (C ≠ A, C ≠ B), для которого

```
t(A,C) + t(C,B) ≤ (1 + α) · t(A,B)
```

Здесь `t` — время из **полной** матрицы этого слоя, а не из уже прореженного графа. Так результат не зависит от порядка проверки рёбер. Равенство удаляет ребро.

**6. Параметр α.** 0,05; 0,10; 0,20. Строятся все три значения, чтобы показать, как результат зависит от допуска на обход. Чем больше α, тем больше рёбер считается «лишними».

**7. Вес ребра.** Время в секундах (`weight_unit = 'sec'`). Меньше — лучше.

Слоёв три, значений α три, поэтому версий графа девять.

## Как читать результат

Граф показывает, какие города соединены без «промежуточной остановки» в смысле времени. Рёбра остаются там, где обход через третий город был бы заметно дольше. Это разреженный каркас сети, а не карта реальных дорог и рейсов.

Что граф **не** показывает:

- вместимость: сколько людей или грузов можно перевезти;
- цены на поездки;
- расписание: время в источнике оценено по средней скорости, а не по расписанию;
- пересадки между видами транспорта;
- реальную физическую сеть. Ребро Москва → Орёл не обязано соответствовать отдельной дороге или рейсу.

Данные о прямых рейсах и расписаниях появятся после работы с данными Яндекса. До этого выводы об устойчивости, которые строятся на этом графе, нужно считать приближёнными.

Прореживание может разорвать достижимость. Каждое удалённое ребро имеет обход в полной матрице, но рёбра этого обхода сами могут быть удалены через другие города. Поэтому для каждой версии считается число пар, которые есть в матрице, но недостижимы по рёбрам графа.

## Что не входит в версию 1.0

Центральность, доступность и устойчивость считаются отдельными задачами на готовых версиях графа. Запись в PostgreSQL (`graph_snapshot`, `graph_node`, `graph_edge`) описана в [модели данных](data-model.md) и реализуется во второй части задачи.
