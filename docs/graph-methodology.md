# Методика построения графа

Версия методики: `1.0`. Задача: [#28](https://github.com/AlexKeyyyy/transport-connectivity/issues/28). Код: `src/transport_connectivity/graph.py`.

## Зачем нужна методика

Набор «Если быть точным» — это матрица «каждый с каждым»: для каждой из 180 × 179 направленных пар городов и каждого из трёх видов транспорта есть оценка времени в пути ([контракт данных](data-contract.md)). Если считать каждую запись ребром, граф окажется почти полным: из каждого города можно «напрямую» попасть в 179 других. В таком графе любой город достижим из любого за один шаг, поэтому ключевых узлов нет: все города одинаково важны. Удаление ребра тоже ничего не моделирует: закрытая дорога Москва — Орёл не закрывает пару Москва → Орёл, а только убирает одну запись.

Реальная сеть устроена иначе. Из Москвы в Орёл едут через Тулу, и отдельной «прямой связи» нет. Поэтому из матрицы нужно оставить разреженный граф: ребро сохраняется только тогда, когда оно не сводится к пути через другой город. Решение об отделении измерения от ребра зафиксировано в [ADR 0003](adr/0003-measurement-vs-graph-edge.md). Эта методика — то самое утверждённое правило, по которому измерение становится ребром.

## Пример на реальных данных

Слой `best`, α = 0,05 / 0,10 / 0,20.

| Участок | Время, с |
|---|---:|
| Москва → Орёл (напрямую) | 24 480 |
| Москва → Тула | 10 440 |
| Тула → Орёл | 10 440 |
| Москва → Тула → Орёл (сумма) | 20 880 |
| Отношение обхода к прямому времени | 0,8529 |

Обход через Тулу даже короче прямого пути: время в источнике оценено по средней скорости, а не по реальной дороге. Поэтому ребро Москва → Орёл удаляется при всех трёх значениях α, а условие `≤` выполняется уже при α = 0.

## Принятые решения

**1. Вершины.** Все 180 городов. Город без рёбер остаётся вершиной: изолированность — тоже результат.

**2. Время по видам транспорта.** Берётся `route_measurement.duration_sec`.

- `road`, `rail` — как в источнике.
- `air` — время источника плюс `AIR_ACCESS_SEC = 10 800` с (3 часа): дорога в аэропорт и из него, регистрация, ожидание.
- Нет измерения (`NULL`) — нет связи этим видом. Источник не утверждает, что маршрута точно нет, поэтому в графе такая пара просто не получает ребра этого вида.

**3. Слои.** Три слоя: `road`, `rail` и `best`. Для пары (A, B) слой `best` берёт минимум из доступных времён трёх видов после поправки для `air`. У ребра запоминается вид, давший минимум; при равенстве выигрывает `road`, затем `rail`. Одно ребро `best` — это одна поездка одним видом транспорта. Путь по нескольким рёбрам может менять вид между рёбрами (например, поезд до Тулы, затем автомобиль до Орла), но время и неудобство пересадки отдельно не моделируются: в сумму входят только времена рёбер и, для самолёта, константа `AIR_ACCESS_SEC` внутри ребра.

**4. Направление.** Граф направленный: A → B и B → A — разные рёбра с разным временем.

**5. Прореживание.** Ребро A → B удаляется, если есть город C (C ≠ A, C ≠ B), для которого

```
t(A,C) + t(C,B) ≤ (1 + α) · t(A,B)
```

Здесь `t` — время из **полной** матрицы этого слоя, а не из уже прореженного графа. Так результат не зависит от порядка проверки рёбер. Равенство удаляет ребро. Оба конца ребра исключены из кандидатов на обход: C не может совпадать ни с A, ни с B.

Параметр α ограничивает обход, который проверяется в исходной матрице. Он не ограничивает кратчайший путь в готовом графе. Если одно ребро заменено обходом, который на α длиннее, а рёбра этого обхода сами удалены через другие обходы, то допуски складываются, и итоговый кратчайший путь по графу может оказаться длиннее прямого времени больше чем на α. Предельный случай такой цепочки — потеря достижимости, см. раздел «Недостижимые пары».

**6. Параметр α.** 0,05; 0,10; 0,20. Строятся все три значения, чтобы показать, как результат зависит от допуска на обход. Чем больше α, тем больше рёбер считается «лишними».

**7. Вес ребра.** Время в секундах (`weight_unit = 'sec'`). Меньше — лучше.

Слоёв три, значений α три, поэтому версий графа девять.

## Как читать результат

Граф показывает, какие города соединены без «промежуточной остановки» в смысле времени. Рёбра остаются там, где обход через третий город был бы заметно дольше. Это разреженный каркас сети, а не карта реальных дорог и рейсов.

Что граф **не** показывает:

- вместимость: сколько людей или грузов можно перевезти;
- цены на поездки;
- расписание: время в источнике оценено по средней скорости, а не по расписанию;
- время пересадки между видами транспорта: путь по рёбрам `best` может менять вид, но пересадка отдельно не учитывается;
- реальную физическую сеть. Ребро Москва → Орёл не обязано соответствовать отдельной дороге или рейсу.

Данные о прямых рейсах и расписаниях появятся после работы с данными Яндекса. До этого выводы об устойчивости, которые строятся на этом графе, нужно считать приближёнными.

Прореживание может разорвать достижимость. Каждое удалённое ребро имеет обход в полной матрице, но рёбра этого обхода сами могут быть удалены через другие города. Поэтому для каждой версии считается число пар, которые есть в матрице, но недостижимы по рёбрам графа.

## Результат: девять версий

Расчёт: `python scripts/data/graph_report.py` на снимке `tochno_intercity_v20260629` (96 660 измерений, 180 городов).

| Слой | α | Вершин | Пар в матрице | Рёбер | Средняя исходящая степень | Недостижимых пар |
|---|---:|---:|---:|---:|---:|---:|
| road | 0,05 | 180 | 29 756 | 3 866 | 21,48 | 0 |
| road | 0,10 | 180 | 29 756 | 2 224 | 12,36 | 0 |
| road | 0,20 | 180 | 29 756 | 1 198 | 6,66 | 0 |
| rail | 0,05 | 180 | 28 056 | 934 | 5,19 | 0 |
| rail | 0,10 | 180 | 28 056 | 702 | 3,90 | 664 |
| rail | 0,20 | 180 | 28 056 | 488 | 2,71 | 17 236 |
| best | 0,05 | 180 | 30 554 | 5 642 | 31,34 | 0 |

| best | 0,20 | 180 | 30 554 | 1 350 | 7,50 | 2 054 |

Средняя исходящая степень — число рёбер, делённое на 180. «Пар в матрице» — сколько направленных пар слоя имеют время; полная матрица содержит 32 220 пар, но у части пар источник не даёт времени (для `best` — ни одним видом транспорта). В слое `best` минимум дал автомобиль для 23 206 пар, самолёт для 6 610 и поезд для 738.

### Недостижимые пары

В шести версиях из девяти недостижимых пар нет. Исключения: `rail` при α = 0,10 (664 пары), `rail` при α = 0,20 (17 236 пар из 28 056) и `best` при α = 0,20 (2 054 пары из 30 554).

Причина в самом правиле. Каждое удалённое ребро A → B имеет обход A → C → B в полной матрице, но рёбра этого обхода сами могут быть удалены через другие города. При α = 0 цепочка замен всегда заканчивается: рёбра обхода строго короче удаляемого. При α > 0 одна часть обхода может быть длиннее удаляемого ребра, и цепочка способна замкнуться. Тогда ребро удалено, а путь, который его оправдывал, тоже разрушен.

Версия `rail` при α = 0,20 теряет больше половины пар, и использовать её для анализа связности нельзя. Версии `rail` при α = 0,10 и `best` при α = 0,20 теряют небольшую долю пар; их результаты нужно читать с учётом этих потерь.

## Что не входит в версию 1.0

Центральность, доступность и устойчивость считаются отдельными задачами на готовых версиях графа. Запись в PostgreSQL (`graph_snapshot`, `graph_node`, `graph_edge`) описана в [модели данных](data-model.md) и реализуется во второй части задачи.
