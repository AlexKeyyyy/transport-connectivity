# Ключевые узлы и устойчивость транспортного графа

Офлайн-эксперимент [#35](https://github.com/AlexKeyyyy/transport-connectivity/issues/35)
от 24 ноября 2026 года. Вход — успешная нормализация снимка «Если быть точным»
`tochno_intercity_v20260629`, 180 вершин и 96 660 измерений. Код прореживания
взят из [закреплённого коммита PR #40](https://github.com/AlexKeyyyy/transport-connectivity/commit/c0117c7990bac37da1124a9666d26e5e786418f5).
Скрипт сверяет SHA-256 обоих нормализованных файлов по отчёту и хеш `graph.py`.

## Методика

Вершины — города с ID из нормализованного снимка. Рёбра направлены, вес —
время в секундах. Слои `road` и `rail` берут время источника. Слой `best`
выбирает минимум, прибавляя к полётному времени 10 800 с. В каждой версии
прореживание удаляет ребро, если в полной матрице есть обход через третий
город не дороже `(1 + α)` от времени пары. Отсутствующие времена пропускаются.
Ход эксперимента фиксирует α = 0,05 / 0,10 / 0,20.

Для кратчайших путей использован алгоритм Дейкстры, для взвешенного
посредничества — алгоритм Брандеса. Равные кратчайшие пути делят вклад,
нормировка для направленного графа — `(N − 1)(N − 2)`. В сценарии удаления
город исключается из отправлений и назначений в обоих вариантах. До удаления
он может участвовать в пути. Потеря достижимости — разность числа пар с
путём. Среднее время сравнивается на парах, сохранивших путь в обоих вариантах.
Рейтинг удаления отсортирован сначала по потерянным парам, затем по росту
среднего времени.

Для добавления связи берём меньшее из текущего и нового веса по каждому
направлению. Доступное население — сумма населения городов, достижимых за
21 600 с, без города отправления. В этом снимке пропусков населения нет.
Пропущенное население давало бы нулевой вклад в сумму.

Для инженерной оценки конкретной связи понадобятся маршрут, вид транспорта и
проверенное время поездки.

## Воспроизведение до слияния PR #40

Из корня ветки #35 в PowerShell. Нормализованный снимок получают командами
`download` и `process` из [инструкции по данным](../data/README.md).
Передайте путь к нему и используйте Python 3.12+ с установленным пакетом.
Временный worktree содержит ровно закреплённый `graph.py`; скрипт #35 и
результаты остаются локальными.

```powershell
git fetch origin
git worktree add --detach ../transport-graph35 c0117c7990bac37da1124a9666d26e5e786418f5
$graphWorktree = (Resolve-Path ../transport-graph35).Path
Copy-Item src/transport_connectivity/resilience.py "$graphWorktree/src/transport_connectivity/"
$env:PYTHONPATH = "$graphWorktree/src"
python scripts/data/resilience_report.py --snapshot data/normalized/tochno_intercity_v20260629 --output data/normalized/resilience-35.json --rank-removals
```

Полный прогон на Python 3.12.3 и Windows 11 Pro, Intel Core i5-12400F,
занял 47,243 с, пиковый рабочий набор процесса 153,02 МиБ. Замер выполнен
`benchmarks/measure.py` из #37, без чтения из SQL и без запуска GDS.
SHA-256 исходного CSV
`aed8463339b988a7c9ac81aa976a4fc25c152e4066b551d25cbdcc16ebe16d53`,
нормализованных измерений
`719f0d87035242548b72ee0764b9c7f4ddd35a077af708ecfec8bba04d2248e6`.

## Условия полной приёмки

Публикация результатов в `analysis_run` и `metric_result` требует готовых
версий графа в PostgreSQL из второй части #28, интеграции с #33 и проекции
[#34](https://github.com/AlexKeyyyy/transport-connectivity/issues/34).
На этой проекции нужно сверить GDS с Python на срезе из 10 городов
с допуском 10⁻⁶ и повторить запись без дублей. Матрица оценивает время по
средней скорости и складывает времена рёбер без дополнительного времени
пересадки. Эффекты показывают свойства модели при выбранных параметрах.
