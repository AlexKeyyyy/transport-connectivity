# ADR 0003. Измерение поездки отделено от ребра графа; граф версионируется

Статус: принято. Дата: 13 ноября 2026 года. Задача: [#4](https://github.com/AlexKeyyyy/transport-connectivity/issues/4).

## Контекст

CSV связности содержит оценку поездки для каждой направленной пары из 180 городов и
трёх видов транспорта — это матрица «откуда — куда», а не сеть непосредственных связей.
Если считать каждую строку ребром, получится почти полный граф: кратчайшие пути и
показатели центральности потеряют смысл, а удаление строки не моделирует закрытие дороги.

## Решение

- `route_measurement` хранит наблюдение источника как есть: направление, вид транспорта,
  расстояние и время с указанием снимка.
- `graph_edge` появляется только по утверждённой методике и принадлежит конкретной
  версии графа `graph_snapshot`. Ребро может ссылаться на измерение, из которого получено.
- `graph_snapshot` хранит версию методики, параметры и все входные снимки
  (`graph_snapshot_input`); состав вершин хранится явно в `graph_node`.
- Каждый расчёт (`analysis_run`) ссылается на версию графа, алгоритм, параметры, сценарий
  и commit кода.

## Рассмотренные варианты

- Одна таблица «связи» для измерений и рёбер: проще, но смешивает факты источника с
  результатом методики; при смене методики пришлось бы менять исходные данные.
- Граф без версий: результаты расчётов нельзя было бы сравнить и воспроизвести после
  изменения данных или параметров.

## Последствия

- Матрица времени поездки пригодна для анализа доступности. Для анализа устойчивости
  нужна модель непосредственных связей (дорожный граф, расписания) — это отдельный этап.
- Смена методики создаёт новую версию графа; старые результаты остаются сравнимыми.
- Схема и ограничения — в [модели данных](../data-model.md).
