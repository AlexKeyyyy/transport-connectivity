# Источники данных и первичная выгрузка (M0-1)

Дата получения динамических данных: **9 октября 2026 года (UTC)**. Срез относится к 10 городам Центрального федерального округа: Москва, Тверь, Ярославль, Владимир, Рязань, Тула, Калуга, Смоленск, Брянск и Орёл. Это фиксированный пилотный набор; список не претендует на полный перечень городов округа.

## «Если быть точным»: транспортная связность

- Карточка и описание: https://tochno.st/datasets/intercity_connectivity
- Исходная CSV-выгрузка в ZIP: `https://storage.yandexcloud.net/tochno-st-catalog/Geo/data_intercity_connectivity_162_v20260629/data_intercity_connectivity_162_v20260629_csv.zip`
- Период набора: 2026; версия публикации от 29.06.2026; лицензия, указанная на странице, — CC BY 4.0.
- В архиве прочитан CSV `data_intercity_connectivity_162_v20260629.csv`: 96 660 строк, 22 поля, UTF-8, разделитель `;`. Архив скачивается в игнорируемый `data/raw/`.
- Sample `data/samples/intercity_connectivity_sample.csv` сохраняет исходные названия полей и значения для направленных пар 10 выбранных городов: 270 строк (90 для каждого из `road`, `rail`, `air`). Одна запись — направленная пара городов и вид транспорта.
- Поля: названия и регионы отправления/назначения (`city_from`, `region_from`, `city_to`, `region_to`); коды ОКТМО (`oktmo_from`, `oktmo_to`) и идентификаторы территории СберИндекса (`sber_territory_id_from`, `sber_territory_id_to`); флаги региональных столиц (`is_capital_*`); население (`population_*`, человек); координаты (`lat_*`, `lon_*`, градусы WGS84); вид транспорта (`transport_type`); расстояние (`distance_km`, км); время (`distance_hr`, ч); `missing_reason`, `source`, `comment` — поясняющие исходные поля.
- В пилоте обнаружено 90 строк без расстояния и времени; причина дана источником в `missing_reason` (маршрут не найден). Эти пропуски сохранены, не заполнялись искусственно. Во всех 270 строках координаты присутствуют и валидны; дубликатов строк нет.
- Для транспортного графа особенно полезны идентификаторы/названия городов, направленность пары, тип транспорта и значения расстояния/времени. Это внешний набор измерений, а не наши собственные расчёты.

## OpenStreetMap через Overpass API

- Источник OSM и условия: https://www.openstreetmap.org/ и ODbL 1.0; малый запрос выполнен через https://overpass-api.de/api/interpreter.
- В `cities.csv` получено 10 OSM-объектов с `place=city|town`: `osm_id` (тип/ID OSM), имя, тип, координаты. Регион и население взяты для тех же городов из вышеуказанного внешнего датасета; `source` в CSV это явно отмечает. OSM-объекты привязаны к связям измерений через OSM-derived `city_id`; это не ОКТМО.
- Актуальность ответа Overpass на момент запроса: `2026-10-09T16:51:36Z` (см. `extraction_metadata.json`).
- В `road_segments_sample.geojson` — 150 дорожных OSM ways в ограниченном прямоугольнике Москвы `55.74,37.58,55.78,37.66` (порядок bbox: юг, запад, север, восток). Поля свойств: OSM way ID, `highway`, `name`, `oneway`, `maxspeed`, `surface`; геометрия — GeoJSON LineString в порядке координат [longitude, latitude]. Отсутствующие OSM-теги оставлены пустыми.
- Дорожные атрибуты/геометрии пригодны для будущего road graph, но этот небольшой bbox-срез не является полной связанной сетью маршрутов между городами. PBF ЦФО (около 839 МБ) не скачивался.

## OSRM Table Service

- API и описание результата: https://project-osrm.org/docs/v5.24.0/api/#table-service
- Запрос: публичный сервер `https://router.project-osrm.org`, профиль `driving`, Table Service, входные координаты из `cities.csv`, `annotations=duration,distance`.
- `route_measurements.csv` содержит 90 направленных пар без диагонали для 10 городов. `distance_m` измеряется в метрах, `duration_sec` — в секундах; также сохранены ID/имена пары, URL роутера, время запроса UTC и `data_version` из ответа.
- Ответ получен 2026-10-09; сервер не вернул `data_version` (90 пропусков в поле), поэтому версия OSM-основы у этой live-службы не зафиксирована. Значения — маршрутизируемые оценки стороннего публичного сервера; при изменении его дорожного графа возможен иной результат. Для повторяемых расчётов потребуется собственный OSRM с закреплённым снимком OSM.
- RouteMeasurement — транспортное измерение между городами, а не автоматическое ребро аналитического графа.

## Воспроизведение и профилирование

Из корня репозитория, Python 3.12+:

```bash
py scripts/data/download_samples.py
py scripts/data/profile_samples.py
```

Первый скрипт скачивает внешний архив только в игнорируемый `data/raw/`, формирует срез, выполняет запросы Overpass и OSRM и сохраняет время/версии ответов. Второй проверяет число строк и полей, типы, пропуски, дубликаты, координаты, числовые диапазоны, ссылки на city IDs и размеры файлов, пишет `data/samples/data_profile.json` и собирает небольшую копию пакета в `deliverables/m0/data-preview/`. Воспроизводимость структуры гарантируется; live OSM/OSRM могут обновляться.

Все CSV сгенерированы скриптом, записаны в UTF-8. Исходный архив, полный PBF и секреты в Git не добавляются.
