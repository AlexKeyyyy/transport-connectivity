# Сценарии проверки skills

При изменении skill дать агенту один запрос и минимальные исходные данные из
сценария ниже. Сохранить фактический ответ/артефакт вне skill и сверить результат;
не подсказывать ожидаемый ответ в самом пользовательском запросе.

Эти сценарии — ручные поведенческие проверки, не автоматически исполняемые тесты.
Структурные CI-checks не выставляют им оценку и не подменяют интеграцию с сервисом.
Для текущей версии выполнены авторская проверка и независимый read-only прогон
четырёх запросов отдельным агентом: OD-сценарий, Neo4j без сервера, bulk с частичным
сбоем и нормализация трёх строк. Ответы соответствовали указанным критериям.
По замечаниям уточнены политика частичных ошибок и граница композиции OD-весов.
Это оценка предложенных решений; live-интеграции с сервисами пока нет.

| Запрос для проверки | Ожидаемое поведение | Ошибка, которую ловим |
|---|---|---|
| «Разбей получение данных, граф и UI на задачи для трёх участников» | transport-task: отдельные принимаемые результаты и зависимости без придуманных сроков | Один гигантский Issue, дублирование AGENTS.md |
| «Обработай A→B: 1.5 часа, 12 км; B→A: маршрут не найден; третья строка с NaN» | transport-data-pipeline: 5400 секунд/12000 метров; обратная пара сохраняет направление и пропуск; NaN учитывается как ошибка | Пропуск превращён в 0; молча потеряна строка |
| «В OD-матрице удалим Москва→Тверь и оценим закрытие дороги» | transport-graph-methodology: объяснить отсутствие road dependencies и предложить корректно ограниченную модель | Физическая устойчивость выведена из удаления записи матрицы |
| «Найди города в 10000 метрах: geometry(Point,4326)» | transport-postgis: geography или обоснованный CRS, корректные оси и индекс | ST_DWithin с 10000 градусами или ST_SetSRID вместо преобразования |
| «Спроектируй Neo4j без сервера: ребро с временем, расстоянием и видом транспорта» | transport-neo4j: свойства допустимы на связи; сервер/версия не выдумываются; результат обозначен как проект | Лишний промежуточный узел только из-за трёх свойств; заявление о live-проверке |
| «Проверь bulk cities: HTTP 200, errors=true» | transport-elasticsearch: проверить items, сообщить/учесть частичный сбой; готовность не объявлять | HTTP 200 принят за успех всех документов |
| «Создай notebook эксперимента» | jupyter-notebook: запустить repo helper, валидный notebook, без обязательного uv/глобальных путей | Не найден helper или молча перезаписан существующий файл |
| «Два smoke-теста прошли, значит полный dataset обработан?» | transport-verify: отделить тесты от полного прогона, запросить run-report/баланс | Все Acceptance Criteria объявлены выполненными без доказательств |

Для графового кода отдельный эталон: A→B=2, B→C=3, A→C=10. Минимальная стоимость
A→C равна 5, C→A недостижим. Если веса означают частоту, этот же расчёт без
преобразования не имеет прежнего смысла. При появлении алгоритма пример становится
его unit/integration-тестом; пока это проверка будущей методики.

Порядок дальнейшей оценки: выбрать затронутые сценарии, получить фактический ответ,
зафиксировать успех/ошибку с причиной, исправить узкую инструкцию и повторить.
При изменении runtime helper дополнительно выполнить его на временном входе.
