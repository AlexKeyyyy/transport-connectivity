# Проверка результата и передача

Прочитай Issue и фактический diff. Сопоставь каждый критерий с файлом, командой
или наблюдаемым результатом. Не отмечай невыполненное как готовое.

Из корня репозитория в Python 3.12+ окружении:

```bash
python scripts/dev/check.py
```

Команда проверяет harness, запускает Ruff и pytest; не скачивает данные, не обращается
к live API и не поднимает сервисы. Для проверки одних skills/ссылок без dev-зависимостей:

```bash
python scripts/dev/check_harness.py
```

Добавь только относящиеся к изменению проверки: offline-fixtures для преобразований,
реальную БД/миграции при их наличии, полный прогон если он требуется Issue, рендер
диаграмм для визуального результата. Укажи пропущенную интеграционную проверку и
причину; прохождение smoke-тестов не заменяет её.

Для данных проверь единицы, namespace ID, направление, баланс строк, исходный hash
и повторяемость. Для skills — происхождение, изменения от upstream и осмысленный
сценарий из [harness-evals](../../../docs/harness-evals.md); структурный валидатор
не доказывает качество решений модели.

В PR/передаче: конкретное изменение и зачем, проверки с результатом, ограничения
и следующий шаг при незавершённости. Сохраняй пользовательские изменения; merge,
назначения и внешние сообщения выполняются только в рамках запроса пользователя.
