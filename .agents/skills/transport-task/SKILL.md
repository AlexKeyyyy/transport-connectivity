# Короткая задача и передача работы

Прочитай README, [план проекта](../../../docs/project-plan.md) и текущий Issue,
если он задан. Сохраняй требования преподавателя и уже принятые решения.

Для одной задачи укажи:
- Цель: одно предложение о результате для проекта.
- Сделать: 3–5 конкретных действий. При меньшем объёме хватит одного.
- Готово: наблюдаемые результаты и способ проверки каждого.
- Зависит от: Issue и конкретный вход, который он должен дать.

Один ответственный, один отдельно принимаемый результат. Не добавляй сроки без
договорённости, не повторяй AGENTS.md и не превращай чек-лист в учебник. Ссылки
на модель или методику лучше копирования её текста. Отделяй исследование от
реализации, если результат первого меняет контракт второго.

Пример: «Нормализовать полный CSV» принимается по файлам, балансу строк,
тестам и повторному прогону. «Создать весь pipeline, граф, API и UI» нужно разделить.

При передаче незавершённой работы оставь в PR или согласованном документе:
ветку/commit, что уже проверено, оставшийся конкретный шаг и блокировку.
Не создавай постоянный файл статуса для каждого короткого изменения.
Создание Issue, назначение и сообщения команде выполняй в пределах запроса пользователя.
