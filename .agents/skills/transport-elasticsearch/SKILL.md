# Поиск городов в производном индексе

Прочитай контракт City и текущую задачу. Elasticsearch восстанавливается из PostgreSQL;
не подменяй им справочник городов. Для задачи документации достаточно проекта mapping
и запросов с явной пометкой «PoC не запускался».

Mapping определяется примерами запросов: city_id и точные фильтры обычно keyword,
name/aliases — text с нужными subfields/анализатором, population — числовое поле,
location — geo_point. Не полагайся на dynamic mapping. Для location предпочитай
объект {lat, lon}, чтобы исключить путаницу с массивом [lon, lat].

До выбора analyzer и клиента узнай версию сервера и доступные плагины. Проверь на
русских названиях точный/частичный поиск, опечатку, регион и радиус. Непустой ответ
недостаточен: задай ожидаемые ID/порядок для небольшого набора городов.

При загрузке используй стабильный document _id, пакетный bulk и проверяй ошибки
каждого item: HTTP 200 всего запроса не доказывает успешную индексацию. Не меняй
исходные данные из-за требований индекса. Сохраняй версию источника и mapping.

Если задача требует online-переключения: собери новый именованный индекс, проверь
документы/запросы и только затем переключи alias. Не объявляй переключение успешным
без проверки ответа и фактического alias; старый рабочий индекс не удаляй автоматически.
Для маленького учебного PoC такая инфраструктура заранее не требуется.
